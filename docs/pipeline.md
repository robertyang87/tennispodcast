# 全自动管线设计

目标：从选题到上架，只留**一处人工闸**（脚本审定），其余全自动，
骨架克隆 tennislive（spec 驱动 + GitHub Actions + PushPlus 回执）。

## 流程

1. **选题**
   - 先查 `tennis-material-library`（INDEX + records + quotes），已做过的不重报；
   - 优先互动/反差/讨论性强的题，结合当下热点；
   - 产出一句话选题卡，落 `specs/<slug>.json` 的 `editorial` 段。

2. **写稿（spec 驱动）**
   - 从素材库记录的内容采集卡/战术提炼卡起草，不重新看整场；
   - spec 分段标注类型：`narration`（旁白）/ `original_audio`（原声切片，带源与时间戳）/ `bgm`；
   - 金句先行：标题、开场、结尾至少占两处（金句库标准：不可替换）；
   - 目标时长 12–18 分钟（中文约 260–300 字/分钟）。

3. **人审闸（唯一人工环节）**
   - 审稿包：全文稿 + 事实锚清单（每个数据/比分/原话注明官方出处）；
   - 所有者点过才进合成。事实口径沿用 tennislive：单源说法先标旗，发布前官方源复核。

4. **合成**
   - 旁白：Edge TTS 本地版（晓晓=主述，云扬=对谈/引语区分），多音字、人名、
     日期在 spec 里预标读音，沿用 tennislive 配音听审（拼音比对）闸；
   - 原声：按 spec 时间戳用 ffmpeg 从存档源（Release / WTA 金库本地文件）精确切片，
     切点落在完整句子之间，不截断原话；
   - 不克隆任何真人声音做旁白。

5. **混音**
   - BGM 取自 tennislive `assets/bgm/`，音量沿用 36% 规矩，旁白段自动 ducking；
   - 片头/片尾固定品牌段；响度归一到播客常用标准（约 -16 LUFS），真峰值留余量。

6. **质检（自动闸，全过才发布）**
   - ASR 回听：合成音频转写后与稿件比对（拼音比对口径），错读/漏读拦截；
   - 静音段、爆音、时长偏差检查；
   - 原声段与 spec 时间戳抽帧/抽听核对（人物—内容一致性）；
   - shownotes 首行不与标题重复（沿用小红书/推送的老规矩）。

7. **发布**
   - 成品 MP3 上传 GitHub Release（稳定直链）；
   - 生成/更新 `feed/feed.xml`（RSS），提交即分发：小宇宙（RSS 认领）、
     Apple Podcasts、Spotify 同一 feed 自动同步；
   - shownotes 同步生成小红书/微信文案草稿（可选）。

8. **回执与入库**
   - PushPlus 发回执：单集链接 + feed 链接；
   - 按素材库规矩回写 `tennis-material-library` 对应记录的「成片」节
     （栏目/标题/日期/链接），**未入库不算交付完成**；
   - 本仓 `episodes/<slug>.md` 登记本期元数据与回执流水号。
